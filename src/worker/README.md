# WhatsApp campaign worker

Run one persistent worker process for the configured sender with `npm run worker` after applying `drizzle/0001_meta_webhook_inbox.sql`, `0002_contacts.sql`, and `0003_campaigns.sql` in order. The npm command compiles the worker with the installed TypeScript compiler and starts the output. Keep the process supervised so it restarts after a host failure. The dashboard only creates and schedules campaigns; it never sends messages from a web request.

Sending is off by default. Set `WHATSAPP_SENDS_ENABLED=true` only after configuring Meta credentials, the WABA webhook subscription, verified contact consent, and an allowed local sending window: `WHATSAPP_SEND_TIME_ZONE` (IANA name), `WHATSAPP_SEND_WINDOW_START` and `WHATSAPP_SEND_WINDOW_END` (`HH:MM`), and `WHATSAPP_SEND_DAYS` (comma-separated weekdays, Sunday `0`). Optional `WHATSAPP_WORKER_BATCH_SIZE` (1–25, default `5`) and `WHATSAPP_MIN_INTERVAL_MS` (200–60000, default `1000`) bound each claim and sender rate. The worker loads `.env.local` and `.env` when present; host-injected values take precedence.

Operate one process per sender. Recipient claims have a five-minute stale timeout, so multiple processes can prematurely park unsent rows from a long batch. Every send gets a durable attempt before the Meta request, and the worker rechecks consent, opt-outs, sender holds, campaign state, send window, and the approved template immediately before POST. An ambiguous outcome is marked `uncertain` and requires manual reconciliation; it is never retried automatically. Meta acceptance and webhook delivery are separate states in the campaign detail view.

## Sending from Vercel (Workflow)

On Vercel the sender is `src/workflows/campaign-send.ts`, started when a campaign is scheduled, sent now, or resumed. It runs the same `runCampaignWorkerTick()` under a single-sender lease (`drizzle/0011`), sleeps until the send window or the scheduled time, and ends when no campaign has work left. The tick step has retries disabled so a possible Meta send is never repeated. Run `0011` on the Supabase project first. Locally nothing changes: `npm run worker` is the sender and `next.config.ts` skips the Workflow transform unless `VERCEL_DEPLOYMENT_ID` is set. Do not run `npm run worker` and the Vercel sender against the same project at once.
